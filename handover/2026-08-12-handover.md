### 검증
- `npx tsc --noEmit` — 통과 (타입 에러 없음)
- `npx eslint src` — 통과 (초기 1건, `MealLogModal`의 `react-hooks/set-state-in-effect` 룰 위반을 `meals/page.tsx`와 동일한 패턴의 eslint-disable 주석으로 해결)
- `npm run build` — **sandbox에서 실행 불가.** `.next/` 디렉터리가 호스트 마운트(FUSE)라 파일 삭제 권한이 없어 `EPERM: operation not permitted, unlink '.next/...'` 로 실패함. 코드 자체 문제는 아니고 타입체크·린트가 깨끗하므로 빌드도 통과할 가능성이 높지만, **사용자가 터미널에서 한 번 `npm run build`로 직접 확인 필요**

### Git 상태
- `git pull`, `git status`, `git log` 는 세션 초반에 정상 동작했음
- 그러나 코드 작업 완료 후 `git add`를 시도하는 과정에서 **`.git/index.lock`이 다시 발생 — 이전 핸드오버에서 경고한 것과 동일한 이슈**. `rm -f .git/index.lock`도 `Operation not permitted`로 실패해서 sandbox에서는 커밋/푸시를 진행하지 못함
- **커밋되지 않은 변경사항이 로컬에 그대로 남아있음.** 아래 "터미널에서 실행할 명령" 섹션대로 사용자가 직접 실행해야 함
- 세션 중 `npm install`을 한 번 실행했는데 sandbox(Linux arm64)와 실제 개발 환경(macOS)의 npm 버전 차이로 `package-lock.json`에서 무의미한 114줄 diff(`libc` 필드 제거)가 발생함. **이 변경은 되돌려야 함** — 아래 명령에 포함시켰다

## GitHub Actions 시크릿 등록 (사용자 직접)
Mission Control 대시보드가 인증을 요구하는지 아직 확인되지 않았다. 스크립트는 시크릿이 없어도 무인증으로 동작하도록 만들어뒀지만, 인증이 필요하다면 아래 경로에서 등록:

- 경로: GitHub 레포 → **Settings → Secrets and variables → Actions → New repository secret**
- 이름: `MISSION_CONTROL_TOKEN`
- 값: 대시보드 쪽에서 발급한 Bearer 토큰 (사용자가 이번 요청에 직접 남겨준 토큰이 있다면 그 값)

등록 후 GitHub 레포의 **Actions 탭 → "Report progress to Mission Control" → Run workflow**로 수동 실행해서 로그를 확인하고, Mission Control 대시보드에 `project:pickup` 카드가 실제로 갱신되는지 확인해줄 것.

## 적용 대기 중인 Firestore 규칙 (B안) — 아내 이메일 확보되면 적용
Firebase 콘솔 → Firestore Database → 규칙 탭에서 아래 텍스트의 `WIFE_EMAIL_HERE` 부분만 실제 이메일로 바꿔서 게시하면 됨:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /{document=**} {
      allow read, write: if request.auth != null &&
        request.auth.token.email in [
          'everydayumay@gmail.com',
          'WIFE_EMAIL_HERE'
        ];
    }
  }
}
```
